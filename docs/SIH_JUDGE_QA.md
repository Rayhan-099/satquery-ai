# SIH 2026: Judge Q&A Guide

Prepare these concise answers for the SIH 2026 hackathon presentation. Our strategy is radical honesty, emphasizing scientific integrity over hype.

### 1. "What is novel about SatQuery AI?"
*Our differentiator is the orchestration.* We did not just plug satellite metadata into ChatGPT. SatQuery translates natural language into a deterministic analysis plan. It selects specific Earth Observation tools (like NDVI or SAR arithmetic), computes actual pixel-level evidence using NumPy/Rasterio, and only then uses an LLM to explain the statistical result.

### 2. "Why not just use ChatGPT or a Vision-Language Model?"
Generic VLMs hallucinate terribly on scientific remote sensing data. They do not understand the numerical pixel values of Sentinel-1 backscatter, nor do they understand invisible multi-spectral wavelengths. Our system uses true math for the science, and an LLM only for the translation layer.

### 3. "How do you prevent hallucinations?"
We use a deterministic fallback mechanism. When the LLM (SmolLM-135M) generates a response, our `EvidenceValidator` intercepts it. Using Regex, it extracts every single number the LLM generated and strictly compares it to the deterministic statistics generated by our EO toolkit. If they don't match, the LLM output is entirely discarded, and a deterministic text template is shown instead.

### 4. "Does it support Sentinel-1 and Sentinel-2?"
Yes. Both are processed through completely independent, modality-specific pathways. Sentinel-2 goes through optical indexing (NDVI/NDWI) using B03/B04/B08. Sentinel-1 is routed through SAR arithmetic handling VV and VH polarization bands.

### 5. "Is this real satellite data?"
*If credentials are active:* Yes, the system uses the Copernicus Data Space Ecosystem (CDSE) OData protocol to pull live data authenticated via Keycloak.
*If using fallbacks:* To ensure our demo is not reliant on hacky conference WiFi or expiring CDSE tokens, we are currently demonstrating using `SYNTHETIC_FIXTURE` mock data. However, as shown in the UI provenance tag, the system tracks exactly where data came from, fully supporting `REAL_COPERNICUS` queries.

### 6. "What datasets did you use for training?"
None. We consciously deferred dataset-specific fine-tuning (like BigEarthNet) for this MVP. We prioritized a zero-shot, tool-calling deterministic architecture over a black-box machine learning classification model to preserve scientific explainability. 

### 7. "What happens when the system doesn't know?"
It safely returns "Insufficient Evidence." If you ask it to identify crop species or count buildings, it explicitly refuses, lists the tools it *does* have, and prevents any LLM from guessing.

### 8. "Is it multimodal?"
Yes, but in the analytical sense. It can process both Optical and SAR modalities. It does *not* contain a "joint latent fusion" model. True pixel-level data fusion is a deferred goal for a future phase.

### 9. "Can this scale?"
Yes. The FastAPI + React + PostgreSQL architecture is standard for production. The primary bottleneck is downloading full SAFE archives from CDSE. In a production cloud environment, we would use GDAL's virtual file systems (`/vsicurl/`) to extract only the necessary `.jp2` bands over the network instead of downloading entire products.
